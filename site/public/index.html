Agentic development, built for teams.

Every task gets its own git worktree and its own terminals, with a coding agent in each — and your teammates can watch any pane from their own machine, and type into it once you allow them.

The window

Three worktrees, four panes, and no question about which one stopped.

Every pane in every worktree carries what it is doing — working, waiting, finished, failed — and how long since it last said anything. teamree watches a PTY, not an agent’s protocol, so “waiting” means the output stopped, not that the agent asked you something.

01 — Worktrees

Start five things at once. Keep five checkouts apart.

Add a repository, then start a worktree from any point in its history. Each is its own checkout on its own branch: five attempts at the same task never see each other’s files, and abandoning one is deleting a directory, not unpicking a commit.

  • Start from a base ref, a local branch, a tag, a commit or a remote branch
  • Created in the background, with progress and a recoverable failure
  • Listed against real git state, not against what teamree last remembered
  • Delete the worktree, and its branch with it if you say so

Status per worktree comes from watching the checkout rather than polling it, so an edit an agent makes inside a ten-minute shell session moves the chips immediately. A panel shows the changed paths and the patch for any of them.

See what changed, tick what should go in, commit it, and check whether the branch would merge into its base, answered in memory. Push when it is ready. There is no force push and no flag to ask for one.

02 — Terminals

Split the pane. Run the work side by side.

Arbitrarily nested, resizable panes per worktree, with a real PTY behind each one. At startup teamree looks on your PATH for the agents it knows how to resume — claude, codex, gemini, opencode and droid — and offers what it finds; anything else you can still type into a pane yourself.

One view lists every pane in every worktree, ordered by what would make you look: failures first, then work in progress, then waiting, then finished — and within each, the one that has been silent longest. Counts per state sit above it, and a row takes you to that pane.

Quitting kills every shell. A pane running a coding agent returns with its conversation resumed; an ordinary pane returns as a shell in the same directory, and its command is never re-run.

The window is absolute black by default, and every colour in it is yours: four presets, forty-two colours you can edit, and a legibility pass over whatever you build, so an editor this open cannot leave teamree unreadable. Terminals follow the window, all sixteen ANSI colours with them.

03 — The CLI

A surface an agent can hold.

teamree talks to the running app over a local socket, so an agent can create a worktree, open a terminal, run a command and read the output back. The window reflects all of it live.

Every command takes --json and emits exactly one JSON document on stdout, with errors on stderr and exit codes: 0 success, 1 the command failed, 2 you typed it wrong, 3 nothing is running to talk to. If the app is not running it says so and exits 3, rather than hanging. 

teamree worktree create --project app --name "fix login"
teamree worktree wait fix-login
teamree terminal run --worktree fix-login --command "npm test"
teamree worktree changes fix-login --json

04 — Teamwork

Watch a teammate's pane. Ask to answer the prompt it is stuck on.

A teammate’s worktrees appear in your sidebar, and one of their panes opens as a pane of your own — beside your work rather than floating over it, moved, resized and closed like any other, so two teammates side by side is an ordinary thing to do. You can read what a pane is doing and type into it; what you type runs when its owner allows it.

Adding a teammate's key lets them ask to run commands on your machine, as you. Their keystrokes are held until you have been shown who is asking, which pane, and the bytes themselves — then you allow them once, for the session, from now on in that pane, or not at all. Anything nobody answers expires, and they are told so. It is also built so that none of it can be used invisibly: the pane says it is being watched and by whom, typing is attributed live, and every remote write is recorded on your machine with who and when. Mute is instant and yours, and answers the question before it is asked. Be plain about what the prompt is: a guard against accident and inattention — a paste into the wrong window, an answer to a question the pane has already moved past — and not a boundary against somebody who means you harm, who can be allowed once, legitimately, and then type anything. Add the keys of people you would hand an unlocked laptop to.

Every guard sits at the owner’s end: their machine refuses unless your key is on the roster, refuses outright when they have muted the pane, holds the keystroke until they have read it and allowed it, caps one write, and records who typed how much into which pane in a log that survives a restart.

Built, not weathered. All five stages have landed — identity, the relay and presence, watching a pane, typing into one, staleness. Two Macs in two places is the one thing still untested.

What it takes to set up. None of it is inside the app alone:

  • A git repository you can both push to, cloned by each of you, with an origin remote — push access is membership
  • A relay your team deploys, its wss:// URL committed to .teamree/relay
  • Each person's public key committed to .teamree/members/<handle>.pub and pushed — written is not enough
  • Node 20 or newer, a Cloudflare account and one browser sign-in, on whichever machine deploys the relay

Both machines dial out to a small relay that splices their connections together and is never trusted with what crosses it. A team runs its own, as a Cloudflare Worker; the installed app carries it, so deploying is one command from any directory, with no clone of the repository.

Trying teamwork is the walkthrough in order, with what you should see after each step. 

teamree team status app          # on? who is connected? which relay?
teamree team members app         # the roster, as the repository records it
teamree team watch app ana --follow
teamree team type app ana --text y --enter
teamree team requests app        # keystrokes held, waiting on your word
teamree team allow ask_3         # the answer, from a machine nobody is at
teamree team write-log            # every remote keystroke, kept
/Applications/teamree.app/Contents/Resources/relay/teamree-relay deploy

Download, clear one flag, open it.

Why macOS says that, and what it does not mean

Installing

First launch, and the one command it needs.

What macOS shows you, and what to do

teamree is signed ad-hoc, with no Developer ID behind it, so macOS has no way to tell who built it. The first time you open it, macOS refuses, with a dialog whose two buttons are Move to Trash and Done:

“teamree” Not Opened
Apple could not verify “teamree” is free of malware that may harm your Mac or compromise your privacy.

Do not press Move to Trash. It is the prominent button and it is the wrong one — it deletes the app you just downloaded. Press Done.

Nothing has been found wrong with teamree. macOS has not examined it and detected something; it is telling you the file arrived without a certificate naming who built it. What the missing signature costs you is the guarantee that the file was not altered on its way here, and a checksum gives you that by another route — which is why every release publishes one.

  1. Open the .dmg and drag teamree to Applications.
  2. Open it, get the dialog above, and press Done.
  3. Clear the quarantine flag, once. Every file a browser downloads is marked with com.apple.quarantine; removing it tells macOS this is a file you put there on purpose. 
    xattr -dr com.apple.quarantine /Applications/teamree.app
  4. Open it normally. It will not ask again.

There is no “Open Anyway” button in that dialog. Through macOS 14 you could Control-click the app and choose Open; macOS 15 removed that, and on 15 and later — macOS 26 included — the dialog offers no way through at all. If you would rather not type a command, the button does exist elsewhere: after pressing Done, go to System Settings → Privacy & Security and scroll to the Security section, where a line naming teamree appears with Open Anyway beside it. Expect it to ask for your password or Touch ID.

Being exact about that last paragraph, because the rest of this was written from watching a real download install itself: the command above was run against this build and watched to work, the dialog is quoted off the screen, and Done was pressed on it and dismissed it. The System Settings route was not clicked through. Open Anyway is the button macOS ships for this case, but nobody here has confirmed how that pane looks on macOS 26 with teamree in it. If you take that route and it does not match, the command is the one that was tested.

Two silences that look like something worse than they are. Before you clear the flag, open teamree.app from a terminal prints nothing and exits 0, and the app still does not start. The bundled teamree CLI is killed outright — no stdout, no stderr, exit status 137. Neither is a broken build; both are this.

And one thing that will look like failure afterwards. spctl -a -vv says rejected before you clear quarantine and after. Clearing the attribute removes what makes macOS enforce the check; it does not give the app a signature, and nothing short of a Developer ID will make spctl say accepted. The app opens regardless. If you went looking for a way to confirm the fix worked, open the app — do not ask spctl.

Check the download against the release. Compare the output of this against SHA256SUMS.txt, published beside the .dmg on the release page. If they agree, the file you have is the file the build produced. It lists the same digest twice, once under the release’s versioned file name and once under the name you downloaded: one image, published under both. 

shasum -a 256 teamree-mac-universal.dmg

The macOS builds are signed, but only ad-hoc — a signature with no identity attached, which is the floor Apple Silicon needs to execute a binary at all. It is not a Developer ID, it is not notarised, and the .dmg itself is not signed at all. The full account, including what codesign prints if you check, is in docs/install.md.
