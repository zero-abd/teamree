## What changed since 0.1.2

Five things, and the first one reverses a rule you may have been relying on.

### A teammate's keystrokes now wait for you

**On 0.1.x they did not.** A teammate typing into a pane you had shared with
them ran straight away; the keystrokes landed, they were recorded as theirs, and
your only recourse was to mute the pane — which is to say, after the command had
already run.

Now the pane holds them and asks you. The question shows what was typed, with
every control character drawn rather than obeyed, and you allow it **once**, for
**this session**, or **always**. The last two are remembered per teammate per
pane, so an answer about one person at one pane says nothing about anybody else
or about your other panes, and both are listed beside the mute — a permission
you cannot see is one you cannot lift.

Nothing hangs while you think. One question covers a burst of typing rather than
one prompt per keystroke; a question nobody answers expires after a minute, and
the teammate is told it expired, which is a different sentence from being
refused. Their pane says, after a second of quiet, that nothing they typed has
run — a pane at a password prompt echoes nothing, so being allowed would
otherwise look exactly like being ignored. On a machine with nobody sitting at
it, `teamree team requests`, `team allow` and `team deny` answer from the
command line. Muting still wins, instantly and without a prompt: a mute is that
question already answered, and it lifts every standing permission on that pane.

**Be plain about what this is.** It is a guard against accident and inattention:
a colleague answering what they think is a prompt in a pane that has moved on, a
paste into the wrong window, an agent driven by somebody who cannot see what
yours is doing this second. It is not a defence against a teammate who means you
harm — everyone who can push to your repository can already arrange to run code
on your machine, and a prompt does not change that. It stops the ordinary
mistake, which is the thing that actually happens.

### A teammate's pane is an ordinary pane

It used to be a card pinned to the bottom-right corner at 70% of the window: one
at a time, over whatever was underneath it, and gone the moment you looked at
something else. It is a pane now — a cell beside your own, moved and resized on
the same gutter, closed with the chord that closes panes, and walked through by
the next-pane chord. Several can be open at once, so two teammates side by side
is finally something you can do. What made it *not* one of your panes is
untouched: the size stays its owner's, typing is still a request, and the bar
still says whose machine a keystroke lands on.

### Setting up a team says what it is doing

The panel now asks first which end you are on — standing a relay up and
inviting, or joining one that exists — and each step says what the machine at
the other end is waiting on while it is not done, which was the half nobody
could see.

**If step 4 seemed to hang on 0.1.x, this is the fix.** The `git push` streams
git's own progress, says when git has gone quiet, and offers a Stop that stops
it and a Try again that says what to do first. The cause is worth knowing if you
met it: git was told not to prompt, ssh was not, and ssh opens `/dev/tty`
directly to ask for a key passphrase or an unknown host — behind teamree's
window, where nobody can answer. Push now runs ssh in batch mode, so a key the
agent does not hold comes back as a refusal naming the command that fixes it.

### The window is absolute black, and every colour in it is yours

The default ground is a true `#000000`, with the title strip, sidebar and status
rail lit against it. Four presets ship and all forty-two colours are editable:
press **⌘,**, or find Appearance in the command palette. A palette you build by
hand is put through the same legibility pass a shipped one is, so an editor this
open cannot make teamree unreadable. Terminals follow the window, with all
sixteen ANSI colours mapped.

### teamree tells you when a newer version exists

It asks GitHub for the newest release — at most once every six hours, never
while anything waits on it, and not at all once you turn it off — and puts a
card in the corner when there is one.

**It cannot install it for you, and does not pretend to.** These builds are
unsigned, and the mechanism a Mac app uses to replace itself checks the
signature on the replacement and refuses an unsigned one. So the card does the
honest half: what is out, that release's notes, and the download. Installing is
the same drag it was the first time.
